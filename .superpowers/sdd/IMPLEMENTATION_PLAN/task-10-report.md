## Implemented contracts

The declared official Python SDK `mcp==2.1.1` supplies the stdio server and client. `evidra-engine mcp --connection-file <path>` reads the dedicated ACL-protected connection file and forwards to the already-running HTTP engine through `httpx` with environment proxy handling and redirects disabled. It opens no database. Fixed tools are exactly `get_notebook_status`, `list_sources`, `search_evidence`, `read_evidence`, `get_protocol`, `get_matrix`, `propose_extractions`, `propose_note`; Pydantic models provide explicit schemas with extra arguments forbidden. No shell, JS, arbitrary file/URL, provider configuration, approval or publication tool exists. SDK v2 snake_case properties and callback APIs were inspected rather than implementing another protocol transport.

The plugin's privileged `McpCredentials` owner generates 32 random bytes using `getRandomValues`, retains them under the scoped idempotency key for uncertain retries, and clears its map on engine startup/shutdown. The opaque renderer cannot submit a token or control connection paths. Creation returns connection metadata and executable/connection-file paths, without token content. The executable derives from the existing verified engine root and fixed `evidra-engine.exe` manifest contract. Setup displays manual Codex PowerShell/TOML, Claude Code PowerShell and Gemini JSON forms. It does not execute client commands or overwrite configuration. The UI offers explicit buttons, guarded Enter, readonly default, 15-minute/1-hour/24-hour expiry, connection pagination, revocation, expiry/last-used labels and 10-second refresh. Recent activity means a request observed within 30 seconds, not a process-liveness claim. English and Portuguese catalogs include every new label.

`ConnectionService` persists SHA256 credential digests, notebook, immutable snapshot, principal, read/propose capabilities, expiry, session identity, revocation and last-use metadata in `mcp_connections`. The ACL file has only protocol version, fixed loopback host, port and its own MCP credential. File reads/writes occur outside SQLite transactions. Idempotent creation verifies the exact fingerprint and existing private file; an uncertain result does not silently mint another credential. Engine restart invalidates the prior session's connections.

`SessionGuard` distinguishes bridge/admin from MCP credentials. Only `/v1/mcp/gateway/*` accepts an MCP principal. Creating/listing/revoking connections and human reviews remain privileged routes under the scoped notebook/snapshot prefix. `ScopeService` signs internally issued MCP principals including credential kind, connection identity and capabilities, then rechecks persisted connection state, bridge heartbeat and existing source/library access through its before/after guarded transactions. The locked `Database.read_one` avoids a nested `BEGIN` for connection checks inside existing guards. A caller cannot construct a broader principal. Scope is derived from the connection, never tool arguments, and intersects snapshot membership with current grants. Existing 64-KiB HTTP requests, Host/Origin checks and the 1,000,000-character renderer envelope remain intact. The stdio forwarding response is additionally bounded to 1 MB; evidence reads enforce the existing 2400-character excerpt maximum. Status returns document coverage with offset/limit pagination (max20), source counts, revision and limits.

External extraction proposals use the existing MatrixService proposal path, validate original evidence and derive `EXTERNAL_CLIENT` from the principal. `declared_model` remains explicitly unverified; `model` and `run_id` stay null. The schema only permits null `run_id`, and the service independently rejects fabricated runs. Idempotency is namespaced by connection and binds the declared model. These calls create proposals only and cannot update human cells.

`ExternalNoteService` stores immutable revisions in `external_notes`, with original text, original evidence/version references, external connection identity, declared model and separate human review metadata. Notes begin UNREVIEWED; approve/reject requires a privileged human route with expected revision and idempotency. No ResearchRun is fabricated. The UI displays literal text, original excerpts and declared provenance before review. An APPROVED external revision can enter the existing concrete note-preview/approved-write outbox flow. `OutboxService` now receives the shared external-note service explicitly, resolves either artifact family, and requires approved external review before preview. `NotePreview.run_id` is nullable. Native publication still uses the existing NoteBridge and AI/outbox markers. HTML escapes client text and preserves original source versions/citations; the renderer reuses the existing sanitizer. Original external revisions remain unchanged after review.

Python models/OpenAPI remain the source of truth. `McpCommand`, `McpSetup`, generated JSON Schema/TypeScript/validator are consumed by the actual bridge. `DocumentBridge`, `ZoteroBridge` and the real `EngineController.request` route allowlist integrate the commands; connection metadata/revocation can proceed without native content revalidation, while content/proposal operations reuse it.

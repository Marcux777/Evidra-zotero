# Textual attachment ingestion and original views

Text attachments selected through Zotero use the same private file registration, regular-file/reparse validation, immutable SHA-256 versions, current-scope guards and bounded Windows subprocess as PDF ingestion. The source kind remains `text_attachment`. The renderer sends scoped identifiers and parser limits, never paths, file bytes or a parser choice. The native resolver records the attachment MIME type in the snapshot, and the bridge checks it again before registration. Older text snapshots without this provenance require recapture (`SCOPE_STALE`); no filename or content-type guessing substitutes for it. Adding an absent MIME field does not change existing immutable content hashes.

Supported inputs:

- `text/plain`, `text/csv`, `text/tab-separated-values` and `text/markdown`: decoded original text, including line endings and Unicode, is retained without search normalization. CSV is a textual source here, not a table-import command.
- `text/html`: ordered HTML text nodes, with block boundaries and character references resolved. Head, script, style and template content are excluded. No scripts, styles, images or linked resources are executed/fetched.
- `text/xml` and `application/xhtml+xml`: strict XML parsing and ordered text nodes; XHTML excludes the same non-content elements. DTD/entity declarations are explicitly unsupported, including EPUB2/XHTML documents that depend on them.
- `application/epub+zip`: one declared rendition, a validated manifest and all XHTML spine units in reading order, including non-linear units. Each unit must contain extractable text; a missing/unsupported unit or image-only spine unit fails the document explicitly. Navigation/non-spine assets do not substitute for its reading order. Encrypted resources, unsupported compression and multiple renditions are explicit failures.

Encoding is strict UTF-8 by default. UTF-8/16/32 byte-order marks and supported declared encodings (Unicode variants, ASCII, ISO-8859-1 and Windows-1252) are recognized; decoding errors and binary controls fail. Unsupported `text/*` formats, including RTF, remain admitted source descriptors with an explicit `UNSUPPORTED_TEXT_FORMAT` ingestion failure. They never count as successful full-text coverage.

EPUB ZIP entries are read in memory from the verified inherited handle, never extracted to disk. Names, duplicates, encryption and symlink entries are checked. The archive is limited to 10,000 entries; total declared decompressed bytes and each bounded member read must fit the configured file-byte limit. The configured page limit also bounds EPUB spine units. Existing worker memory/time/output/cancellation limits apply. The unpaginated original-text unit is additionally bounded to `min(20,000,000, memory_bytes / 256)` Unicode characters to bound the engine's normalization map; exceeding it pauses with `TEXT_LIMIT`. Limits fail without publishing truncated content. Text reindexing rechecks the parser limits even when its immutable version is already cached.

Original file SHA-256 and byte count identify the original bytes; `evidra-text-file-v1` identifies the extraction policy. Text nodes and EPUB units are joined deterministically before search normalization and chunking. This is extracted original text, not a copy of the raw markup/ZIP file. As with existing PDF snapshots, the source file itself must still exist to inspect those raw bytes later.

Unpaginated text uses one internal storage unit, with no physical page number or label. Its evidence has `precision=text`, `page_index=null`, no rectangles, and offsets into that immutable text. Retrieval and full-scan planning consume the resulting document/chunks and preserve explicit ingestion failures in coverage. Empty plain/markup text is metadata-only; it is not classified as OCR success.

**Native original opening:** “Open original attachment” uses the verified current original file as input. HTML/XHTML and EPUB show its semantic structure: headings, paragraphs, lists, emphasis, table headers/cells/spans/captions, figures and supported embedded images. XML has an exact decoded source view with tags, attributes, whitespace and Unicode preserved as literal text. Plain formats show their exact decoded text. The immutable extracted excerpt remains separately labeled, with its original Unicode offsets and highlight, in segments of at most 16,000 code points. Those offsets are never assigned to the structural DOM, a physical page or an EPUB CFI.

Before every original unit or transport segment, the native bridge reacquires current compound item/MIME/version authorization and the current path. The engine opens the registered Windows handle with the existing identity, reparse, size and immutable SHA-256 checks; the bounded parser reads that same handle. It reuses the successful ingestion's declared limits and compares a SHA-256 of the complete reconstructed extraction with the cited immutable extraction before publishing a unit. Missing, replaced, changed, revoked or mismatched originals are refused. No stored extraction or original-view cache substitutes for this verification.

EPUB resource ranges use the existing `xml_text` output and exact `\n\n` joins. The first overlapping resource is selected by the cited range, with its full first/last resource range disclosed; repeated quote text is not used as a locator. Previous/next controls visit the complete supported spine in order and preserve each original resource name. Only the selected source/tree and the extraction text parts are retained while traversing the archive. Unused non-spine declarations do not change extraction admission. A figure requires exactly one valid manifest declaration for its resolved archive member; missing, conflicting or duplicate declarations do not authorize an image.

The native-only `/documents/original-view` response carries at most 64,000 Unicode code points plus bounded metadata, below 900,000 encoded bytes. Structural units are transmitted in deterministic chunks with total length and SHA-256, assembled and verified only inside the privileged owned view. A large unit is not truncated to fit one response. XML/plain/source inspection uses 64,000-code-point segments. Every additional read repeats the bounded worker and file/scope verification; this avoids a persistent cache but can make large units slower to open. Original data, paths and callbacks are never returned through the React command bridge.

The worker emits a flat passive token grammar rather than raw executable markup. Native code creates only explicitly allowed HTML elements and non-URL structural attributes in an inert template content document, applies a separate DOMPurify 3.4.14 instance, then adds application-created `data:image/png` references for checked PNG assets. The final neutral presentation is an owned `srcdoc` iframe with an empty sandbox and no source scripts, navigation, forms, CSS, nested frames or external URLs. CSP provides an additional restriction; it is not relied on to intercept Zotero's custom attachment channel. The bundled Reader and global protocol/security settings are not used or changed.

PNG, JPEG, GIF and WebP resources embedded in the same file or uniquely declared in the verified EPUB are decoded by Pillow in the bounded worker, limited to the existing preview bound of `min(16,000,000, memory_bytes / 16)` pixels, oriented without cropping, and re-encoded to passive PNG. Animated images, SVG/other formats, unavailable/foreign resources, unsupported base declarations, image limit/decode failures and omitted color profiles have specific inspectable limitations. Original source markup remains available as literal text. Source styling and active-content removals are also listed; CSS-generated content and publisher layout are not reproduced. A representation with omissions is explicitly labeled incomplete, not silently counted as a complete reproduction.

A later verification or rendering failure clears both the original representation and the extracted text, disables continuation, and preserves the causal diagnostic. Source invalidation closes affected owned views. Close, owning-window removal, engine restart and plugin shutdown remove owned content; pending results cannot recreate it. No global resource alias, blob cache or cross-reader policy is installed.

PDF citations retain their existing loaded-stream size/hash verification and exact/page-only navigation. Text attachments do not enter PDF Reader/preview operations. Source regressions exercise the file/hash/authorization boundary and native view logic. The controller summary `.local/native-smoke/resumed-original-native-controller-summary.json` binds 57 checks and eight inspected captures; EPUB table/figure validation uses native DOM/pixel inspection because those elements are below the captured viewport.
